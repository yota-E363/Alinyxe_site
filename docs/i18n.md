# Internationalization

The locale system lives under `src/lib/i18n` and is dictionary-based.

## Main Files

- `src/lib/i18n/locale-context.tsx`: provides the `LocaleProvider` and `useLocale()` hook.
- `src/lib/i18n/types.ts`: defines the dictionary shape and the `Locale` union.
- `src/locales/en.ts` and `src/locales/fr.ts`: language dictionaries.
- `src/locales/index.ts`: locale registry, default locale, and dictionary map.

## Runtime Behavior

- `LocaleProvider` stores the active locale in React state.
- The selected locale is persisted in `localStorage` under `alinyxe-locale`.
- The provider updates `document.documentElement.lang` when the locale changes.
- `useLocale()` returns `{ locale, setLocale, t }`.
- `t` is the active dictionary, so `t.common`, `t.home`, `t.services`, and the rest are the canonical access pattern.

## Common Usage

- Shared navigation and footer labels come from `t.common`.
- Page sections use namespaced keys like `t.home.hero`, `t.home.services`, and `t.home.how`.
- Components should read from the dictionary instead of hardcoding copy when the text is user-facing.

## Adding New Translation Keys

1. Add the new key to `src/lib/i18n/types.ts`.
2. Add the same key to `src/locales/fr.ts`.
3. Add the same key to `src/locales/en.ts`.
4. If a new language is added later, include the key there too and register it in `src/locales/index.ts`.
5. Update any consumers to read from `t` instead of inline strings.

## Adding A New Locale

- Create a new dictionary file under `src/locales/`.
- Add it to the `dictionaries` map in `src/locales/index.ts`.
- Add the locale code to the `locales` array.
- Update the `Locale` union in `src/lib/i18n/types.ts`.

## Practical Rule

- Keep all dictionary objects structurally identical across languages. The TypeScript types are there to catch drift early.
